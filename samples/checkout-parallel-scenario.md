## Context

The TechShop E2E checkout regression suite runs on **4 parallel workers** in CI. It covers adding items to a cart (including as a guest), merging the guest cart on login, applying a promo code, completing checkout, and verifying the order in order history.

## System constraints (facts about TechShop's database and API — treat as given)

| Field / resource | Constraint |
|---|---|
| `user.email` | UNIQUE in the `users` table; registering an existing email returns `422 email_already_in_use` |
| `promo_code` | Single-use per customer; marked `redeemed = true` after the first successful use |
| `guest_session_id` | Single-use; consumed (invalidated) when the guest cart is merged on login |
| `order_id` | Generated by the database on `POST /orders`; the value in the table is what the test *expects*, not what it sends |
| `payment_method_token` | One-time-use Stripe test token; invalid after the first charge attempt |
